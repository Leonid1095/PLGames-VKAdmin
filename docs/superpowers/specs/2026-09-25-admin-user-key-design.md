# Личный ключ админа через веб-кабинет

Дата: 2026-09-25. Статус: дизайн согласован с владельцем в чате («ок делай»).

## Зачем

Ключ сообщества VK не пускает в методы, которые доступны только личному
ключу пользователя-админа (проверено пробами 23.09 и схемой VK API):
`photos.getWallUploadServer` / `photos.saveWallPhoto` (фото к постам),
`wall.deleteComment`, `groups.ban` / `groups.unban`, `wall.pin` / `wall.unpin`.
Сейчас бот в этих местах шлёт админу ссылку «сделайте руками», а автопосты
выходят без картинок. Вносить личный ключ через консоль неудобно и небезопасно.

## Что видит владелец

Дашборд → страница группы → карточка «Ключи и доступы» → строка «Личный ключ
админа»:

- нет ключа — ⚪ «не подключён» и кнопка **«Подключить»**;
- ключ есть и живой — ✅ «подключён: Имя Фамилия (vk.com/idN)» и кнопка
  **«Отключить»**;
- ключ умер (смена пароля, отзыв) — ❌ с ошибкой VK и кнопка «Подключить заново».

«Подключить» ведёт на стандартный экран VK «Разрешить приложению доступ:
стена, фотографии, сообщества, доступ в любое время». После «Разрешить» —
страница «Ключ подключён для групп: …» со ссылкой назад в панель.

## Поток

1. `GET /api/vk/admin-oauth` — только для залогиненного владельца панели.
   Кладёт `state` в отдельную куку `vkadmin_admin_oauth_state` (10 мин,
   httponly, samesite=lax) и редиректит на
   `oauth.vk.com/authorize?client_id=VK_APP_ID&redirect_uri=BASE_URL/api/vk/callback
   &scope=wall,photos,groups,offline&response_type=code&state=…&v=5.199&revoke=1`.
   Redirect URI — тот же, что у подключения групп: он уже разрешён в
   настройках приложения VK, новый регистрировать не надо. `revoke=1` — чтобы
   VK не отдал закэшированный отозванный ключ (урок err 27).
2. VK возвращает на `/api/vk/callback`. Если `state` совпал с админской
   кукой — это админский поток: код меняется на ключ через
   `oauth.vk.com/access_token` (как у групп). Если VK вернул ключ во
   фрагменте (Standalone-приложение), существующий JS шлёт его на
   `/api/vk/callback/token` — там тот же разбор по админской куке.
   Групповой поток не меняется.
3. Проверка: `groups.get(filter=admin)` этим ключом → пересечение с нашими
   активными группами. Ключ сохраняется только для групп, где VK подтверждает,
   что этот человек — админ. Нет ни одной такой группы — отказ с объяснением,
   ничего не сохраняется.
4. Хранение — в `settings` каждой такой группы: `admin_user_token`
   (зашифрован `core.crypto.encrypt_token`), `admin_user_id`,
   `admin_user_name`; `admin_key_error` очищается. Ключ нигде не
   показывается и не пишется в лог. Mini App эти ключи писать не может
   (вне `MINIAPP_SETTING_KEYS`), дашборд их не рендерит.
5. «Отключить» — `POST` с CSRF: стирает эти настройки у группы. Полный отзыв
   доступа — в VK: Настройки → Приложения (подсказка рядом с кнопкой).

## Где бот пользуется ключом

Новый модуль `core/admin_key.py`: `get_admin_api(group_id) -> API | None` и
`report_admin_key_failure(group_id, error)`.

- `core/images.upload_photo_to_vk` — загрузка через ключ админа, если есть;
  иначе как сейчас (ключ сообщества, пост без фото).
- `handlers/comments._moderate` — удаление комментария и автобан через ключ
  админа; не вышло — ссылка админу, как сейчас.
- `core/agent` — `ban_user`, `unban_user`, `pin_post` через ключ админа;
  нет ключа — нынешний ответ «сделайте вручную» дополняется «или подключите
  личный ключ в панели».

Ключ признаётся мёртвым только по ошибке VK 5 (авторизация не прошла):
`admin_key_error` = текст ошибки, одно ЛС менеджерам на новую поломку,
карточка показывает ❌. Прочие ошибки (нет прав на конкретный комментарий,
человек уже в бане) — не повод считать ключ мёртвым.

## Карточка ключей

`core/key_status._admin_key_status` становится живой проверкой
(`users.get` этим ключом, таймаут как у остальных): off / ok с именем /
fail с ошибкой; `where` — «кнопка «Подключить» ниже».

## Риски и неизвестное

- Ключ с `offline` не истекает сам и даёт доступ к стене, фото и сообществам
  владельца в пределах прав. Поэтому: только нужные права, шифрование,
  никакого показа, кнопка «Отключить».
- Не проверено, выдаст ли VK личный ключ этому приложению через
  `oauth.vk.com` (VK переводит авторизацию на VK ID). Первая проверка —
  одно нажатие «Подключить» владельцем после выкладки. Если VK откажет —
  ошибка покажется на странице и в логе, план пересматривается.

## Тесты

- старт: без логина — на вход; с логином — редирект на VK с нужными
  `scope`/`revoke`/`state` и админской кукой;
- колбэк: чужой `state` — отказ; код → ключ → сохраняется зашифрованным только
  для групп, где VK подтвердил админство; ни одной — отказ, ничего не
  сохранено; фрагментный вариант через `/api/vk/callback/token`;
- групповой поток не задет (существующие тесты `test_oauth_security`);
- «Отключить» стирает ключ, без CSRF — не стирает;
- `upload_photo_to_vk`, `_moderate`, `ban_user`/`pin_post` берут ключ админа,
  когда он есть; ошибка 5 помечает ключ мёртвым и шлёт одно ЛС;
- карточка ключей: off / ok / fail.

## Ревизия 25.09.2026: VK ID вместо oauth.vk.com

Живая проверка: `oauth.vk.com/authorize` отвечает `invalid_request / Security
Error` на любой запрос ключа пользователя для приложения 54477693 (при любых
scope/revoke/redirect; подключение групп с `group_ids` по-прежнему
принимается). VK ID (`id.vk.ru/authorize`) приложение и наш redirect_uri
принимает. Поэтому:

- старт: `id.vk.ru/authorize?response_type=code&client_id&redirect_uri&state
  &code_challenge&code_challenge_method=S256&scope=wall photos groups`;
  `state` (≥32 символов) и `code_verifier` — в httponly-куках на 10 минут;
- возврат: `?code&device_id&state` в query → POST `id.vk.ru/oauth2/auth`
  (`grant_type=authorization_code`, `code_verifier`, `device_id`, …);
- ключ живёт 1 час; хранятся ещё `admin_refresh_token` (зашифрован),
  `admin_device_id`, `admin_token_expires_at`. За 5 минут до истечения бот
  продлевает пару (`grant_type=refresh_token`) — под одним замком и сразу во
  всех группах этого админа: после продления старая пара недействительна;
- мёртвым ключ считается и при отказе VK ID продлить (`invalid_grant`,
  `invalid_token`, `access_denied`, `invalid_client`); временные сбои
  (`server_error`, таймаут) — нет;
- ветка ключа во #фрагменте (`/api/vk/callback/token`) убрана: VK ID
  возвращает код в query.
