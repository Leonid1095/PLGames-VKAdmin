# Аудит VKAdmin — 23.09.2026

Повод: «в одной группе есть лайки и комментарии, а в дашборде их нет».
Метод: журнал systemd, живая БД (read-only), безопасные пробы VK API (несуществующие
ID, пустые параметры), схема VK API (`vkcom/vk-api-schema`, поле `access_token_type`),
два параллельных ревью кода (безопасность, корректность) с ручной перепроверкой
каждой находки. Все исправления покрыты тестами: `venv/bin/python -m pytest`.

## Главная причина: лайков и комментариев нет в дашборде

`tasks/analytics.py` читал стену `wall.get` **ключом сообщества**. У `wall.get` в схеме VK
`access_token_type: ["user", "service"]`, поэтому каждые 6 ч VK отвечал error 27
«method is unavailable with group auth» (92 раза в журнале). Джоба при этом писала
«executed successfully», таблица `post_analytics` пустая у обеих групп. Проверено
сервисным ключом: у 236517033 на стене 16 лайков, 2 комментария, 1015 просмотров.

Во веб-дашборде блока статистики не было вообще: цифры показывал только Mini App,
и тоже нули.

**Исправлено:**
- `core/vk_read.py` читает стену сервисным ключом `VK_APP_SERVICE_KEY` и не глотает ошибки VK.
- Сборщик запускается через минуту после старта и дальше раз в час (было: раз в 6 ч, после рестарта до 6 ч без данных).
- В дашборде появилась карточка «Статистика стены»: итоги, таблица постов со ссылками, кнопка «Обновить сейчас» с CSRF.
- `core/group_setup` тоже читал стену ключом сообщества: ИИ настраивался вслепую, без постов.

## Найдено и исправлено

### Безопасность
| # | Уровень | Проблема | Исправление |
|---|---|---|---|
| S1 | HIGH | CSRF: GET `/api/vk/callback/token` принимал готовые токены без OAuth-state. Кука SameSite=Lax, поэтому одна ссылка, открытая владельцем, подменяла токен и админа любой группы | обязательный state из куки; JS передаёт весь fragment |
| S2 | MEDIUM | SSRF: проверялся только первый URL, httpx шёл по редиректам на 127.0.0.1; загрузка картинок вообще без проверки | `web_reader.safe_get`: проверка каждого шага редиректа |
| S3 | MEDIUM | Настройки Mini App принимали любой ключ (`_last_newsletter_at` снимал суточный лимит рассылки) | белый список ключей |
| S4 | MEDIUM | Токен Mini App продлевал сам себя бесконечно; подпись запуска без проверки `vk_ts`/`vk_app_id` | без продления; окно 24 ч; проверка приложения |
| S5 | LOW | `/api/health/llm` публичный: платный вызов LLM, утечка модели и ошибки | только после входа в дашборд |
| S6 | LOW | XSS в Mini App: тип источника или задачи, `source` поста | `escape()` + валидация типа в агенте |
| S7 | LOW | `?gid=` перекрывал группу из подписанного токена на страницах участника | приоритет у токена |
| S8 | LOW | секрет Callback сравнивался через `!=`; лимитер заводил счётчики под мусорные `group_id` | `hmac.compare_digest`; неизвестные группы отбрасываются до лимитера |

### Документация
README описывал несуществующие slash- и !-команды, патч-ноты из GitHub, «пароль = JWT_SECRET»,
авто-баны и аналитику раз в 6 ч. ROADMAP отмечал «удаление → бан» как сделанное.
Исправлены README, ROADMAP, `.env.example` (сервисный ключ обязателен, PostgreSQL не
поддержан) и `deploy.md` (помечен как устаревший).

## Не исправлено: нужно решение владельца

1. **Личный ключ администратора** для удаления комментариев, банов, закрепов и фото.
   Это единственный способ получить эти функции: ключ сообщества VK их не пускает.
   Сейчас бот честно отправляет админу ссылку.
2. **PostgreSQL**: путь из docker-compose несовместим (DateTime без часового пояса, лёгкие миграции только для SQLite). Либо починить, либо убрать из compose.
3. **Часовой пояс**: `datetime-local` в Mini App и `schedule_post` агента трактуются как UTC. Для МСК посты выходят на 3 ч позже.
4. **Mini App-токен в URL** (`?token=`) оседает в access-логах nginx и uvicorn. Правильно передавать его в заголовке, но это переделка фронта.
5. **GITHUB_TOKEN** прикрепляется к любому `github.com/<owner>/<repo>`. Сейчас админ один, и это владелец, поэтому риск теоретический. Решение — белый список владельцев репозиториев.
6. **Мелочи из ревью**, которые стоит сделать позже:
   - `parse_vk_group` не берёт даты постов;
   - `break` в `fetch_and_schedule` даёт один пост на группу за цикл;
   - рассылка не учитывает ошибки 901/6;
   - `grant_vip` сравнивает naive- и aware-datetime;
   - ~20 отдельных сессий БД на один комментарий;
   - `wall_reply_edit` не модерируется.
